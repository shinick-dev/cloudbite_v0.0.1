# gw-shinick (k.shinick.dev) — 자격증명 브로커

남의 PC 에서 내 API 키를 **진짜 키 없이** 쓰기 위한 Cloudflare Worker.

```
빌린 PC  /borrow  ──QR──▶  폰 /a/<id>  ── NFC 보안 키 탭(WebAuthn, PIN) ──▶ 승인
         ◀── kvt_ 가짜 토큰 + base URL (1회 전달)
API 호출 /p/<provider>/…  ── kvt_ → 진짜 키로 교체 ──▶ upstream
```

- 진짜 키는 DO 저장소에 `MASTER_KEY`(Worker secret)로 AES-GCM 암호화돼 있다. OpenRouter 는 세션마다 **$ 한도 서브키**를 만들어 서버에만 두고, 만료·폐기 시 삭제한다.
- 상태는 Durable Object 하나 (강한 일관성 → 폐기 즉시 무효). 토큰은 SHA-256 해시로만 저장.
- 페이지에 외부 스크립트 없음 (CSP `script-src 'self'`).

| 경로 | 용도 |
|---|---|
| `/borrow` | 빌린 PC. QR·코드 → 승인되면 PowerShell/bash 환경변수 줄 표시, "다 썼어요" 로 즉시 폐기 |
| `/a/<id>` | 폰. 요청 위치·IP·브라우저 확인 → 공급자·시간(1/3/8h)·OpenRouter 한도($1/5/10)·호출 상한(총·분당·동시, 낮추기만)·(Daytona 를 고르면) 관리 API 허용(기본 꺼짐) 선택 → 키 탭 |
| `/admin` | 키 탭 후 8시간: 세션 목록, 개별/전부 끊기, **공급자 추가·키 교체·삭제**, 보안 키 삭제, 감사 로그 |
| `/register` | `SETUP_TOKEN` + 키 탭으로 보안 키 등록 (NFC·Nano 각각) |
| `/p/<id>/…` | 프록시. `Authorization: Bearer kvt_…`, `x-api-key`, `xi-api-key` 중 무엇으로 보내도 된다 |

## 공급자

프리셋(`src/providers.ts`): openrouter(세션별 $ 한도 서브키), groq, hf, tavily, elevenlabs, nebius, nvidia, openai, langsmith(`LANGSMITH_ENDPOINT`, 서비스 키면 올릴 때 workspace 를 찾아 `X-Tenant-Id` 고정 헤더로 붙임), daytona(샌드박스·스냅샷 등 데이터 API).

- **Daytona 조직·계정 관리 API**(`organizations`·`api-keys`·`users` 로 시작하는 경로와 `audit/organizations/…`·`webhooks/organizations/…` — 최종 upstream 경로 전체를 앞의 `api`·`v<n>` 만 건너뛰고 본다. 대소문자·`;매개변수`·`%` 인코딩 4겹·`./` `../` 를 풀어서 본다)는 승인 화면에서 따로 켠 토큰만 쓴다 (기본 꺼짐). 허용은 그 공급자 세대(gen)에 묶여 지우고 다시 만들면 사라진다. 허용 표시가 없는 예전 세션은 거부. id 가 `daytona` 이거나 upstream 이 `daytona.io`·`daytona.work` 이거나 env 이름이 `DAYTONA_API_KEY`·`DAYTONA_API_URL` 인 정의는 모두 Daytona 로 본다. Daytona 정의의 upstream 을 이 관리 경로 아래(예: `…/api/organizations`)로 잡는 것은 거부.
- **세션 호출 상한**: 승인·실습실 자리마다 총 10,000회 · 1분 300회 · 동시 10개가 기본이자 최대. 승인하는 사람은 각 값을 1 이상으로 낮출 수만 있다. 확인·예약은 DO 안에서 한 덩어리 (동시 요청도 못 넘음). 키가 upstream 에 가기 전 실패(복호화·요청 만들기)는 돌려주고, 간 뒤(4xx·5xx·연결 실패)는 센다. 동시 자리는 키를 실은 fetch·응답 본문이 살아 있는 동안 5분마다 늘리고(15분 lease), 본문이 끝나거나 끊길 때(받는 쪽이 끊으면 upstream 도 끊음) 풀린다. 늘리기가 멈춘 자리(죽은 프로세스)는 15분 뒤 버린다. 늘리기 때 세션이 끊겼거나 자리가 없어졌으면 upstream 호출을 끊는다. 상한 없던 예전 세션은 첫 호출 때 기본값을 받고 예전 호출 수도 총에 든다. `/admin` 세션 목록에 사용량/상한·진행 중·관리 API 허용 표시.
프리셋에 없는 것도 `/admin` 의 "직접 입력"으로 추가할 수 있다 (upstream https 주소, 인증 헤더 방식, 빌린 PC 환경변수 이름).

```powershell
.\kv.ps1 push                        # User 환경변수에 있는 프리셋 키를 전부 올림 (Nano 터치 1회)
.\kv.ps1 push -Names tavily,openai   # 골라서 (키 교체도 같은 명령)
.\kv.ps1 list                        # 저장된 공급자 (끝 4자리만)
```

`kv.ps1` 은 `/api/cli/login` 으로 관리 요청을 만들고 승인 페이지를 연다. 터미널의 코드와 같은지 보고 키를 터치하면 8시간짜리 관리 토큰을 받는다.

## 금고 (/vault)

로그인 정보 같은 비밀을 종단 간 암호화로 보관한다. 서버는 암호문만 가진다.

- 금고 키(무작위 32바이트)는 브라우저에서만 풀린다. 보안 키마다 PRF → HKDF 로 만든 키로 감싸 저장 (`vwrap:<credId>`).
- 복구: 사용자가 정한 질문·답(대소문자·띄어쓰기 무시) → PBKDF2-SHA256 100만 회 → 감싸기 키 + 검증값. 서버는 검증값 해시만 두고, 맞을 때만 복구용 암호문을 준다 (24시간 5회 오답이면 잠김). 복구로 열면 읽기 전용.
- 항목마다 정책: 폰에서만 보기 / 빌린 PC 로 보내기 허용.
- **빌린 PC 로 보내기**: PC 의 `/recv` 가 ECDH P-256 키를 만들고 QR 을 띄운다 → 폰 `/vault#send=<id>` 에서 키로 금고를 열고 항목을 보낸다 → 그 PC 창만 풀 수 있는 암호문이 서버를 거쳐 간다. 양쪽 화면의 코드는 PC 공개키의 지문이라 서버가 키를 바꿔치기하면 달라진다.
- **자동 로그인**: 빌린 PC 의 PowerShell 에서 `irm https://k.shinick.dev/go | iex` → Edge 를 임시 프로필 + InPrivate 로 띄워(Windows 계정 자동 로그인 차단) `/recv` 를 열고, 받은 로그인으로 사이트에 아이디·비밀번호를 넣고 로그인 버튼까지 누른다(한 화면·두 단계 모두). Enter 를 누르면 Edge 를 닫고 임시 프로필을 지운다. 스크립트는 `src/go.ps1`.
- **다음 사이트**: 항목에 "로그인 후 열 사이트"를 넣으면 로그인(2단계 인증 포함, 최대 5분)이 끝난 뒤 그 사이트를 열고 "Google 로 계속" 같은 버튼 → 계정 선택 → 동의까지 누른다. 예: Google 로그인 + `https://claude.ai`. 제공자는 로그인 주소·항목 이름에서 고른다(google, microsoft, apple, github, kakao, naver, facebook).
- PRF 키 등록: /admin 에 키로 로그인 → 3분 안에 "PRF 키 등록". CLI(kv.ps1) 토큰으로는 등록할 수 없다.

## 공부방 실습실 (/lab)

승인된 수업 화면의 실제 이용 흐름은 [수업 화면 사용 가이드](docs/classroom-flow.md)를 참고하세요. 모임지기 시연실, 세 가지 수업 방식, 참여자 단계 안내, 실제 결과.txt 제출과 피드백을 다룹니다.


모임지기 화면은 **모임 진행 / 개설 요청 / 모임 준비 / 설정**으로 나뉩니다. 모임 진행에서 현재 모임을 고르면 참여자 화면과 도움 대기열이 먼저 나옵니다. **도와주기**는 해당 참여자의 지원 화면을 열고, 클릭·키보드는 별도 **제어 요청**에 참여자가 동의한 뒤 사용합니다. 영상 세션이 없으면 해당 참여자의 서버 상태표로 이동합니다.

중앙의 **내 시연**에서 실제 시연실 파일·명령을 작업하고 **시연 송출 시작**으로 같은 영역을 공유합니다. **참여자 모아보기 ↔ 내 시연 보기** 버튼 하나로 중앙을 전환합니다. 새 도움 요청은 **입장 아이디 · 좌석번호**와 함께 자동 확대되며 추가 요청은 대기합니다. 지원 화면을 보는 동안에도 기본 송출은 내 시연 영역으로 유지됩니다. 클릭·키보드 제어는 참여자 별도 허용 후에만 시작합니다. 코드·초대·복구는 자료·코드와 모임 도구에서, 새 모임·알림·설치·로그아웃은 설정에서 찾습니다. 개설 요청은 참여자 미리보기 위에 표시하고 본인 로그인으로 조회하며 승인할 때 별도로 보안 키를 확인합니다. [중앙 작업 화면 사용법과 검증 범위](docs/classroom-unified-workspace.md). 대형 학습 플랫폼 비교용 포크와 기능별 OSS 후보는 [학습 플랫폼 조사](docs/research/teaching-platforms/README.md)에 정리했습니다.

수업마다 참가자별 Daytona 실습실(브라우저 VS Code + Claude Code·OpenCode)을 한 번에 만들고, 끝나면 한 번에 지운다.

```
강사 /lab (키 탭) ── 자리마다 ──▶ OpenRouter $ 한도 서브키 + kvt_ 세션 + Daytona 샌드박스(스냅샷 gw-lab-v5-*)
                  ── 자리마다 초대 ──▶ lab.shinick.dev/j/<자리 코드> + QR (자리 표의 "초대", 수업 하나짜리 코드는 없음)
참가자 초대 링크 ──▶ 자리 확인 → "입장" → 깨우기 → 수업 자료 넣기 → code-server 켜기
             ──▶ 그 자리 호스트 s-<label>.shinick.dev 로 폼 POST → __Host-lab_seat 쿠키 → 거기서 VS Code
s-<label>.shinick.dev/* ──▶ 쿠키의 자리(label 일치) → Daytona 미리보기 주소 + x-daytona-preview-token (경고 화면 없음, WebSocket 포함)
샌드박스 안 claude/opencode/lab-status ──▶ https://gw-shinick.<계정>.workers.dev/p/openrouter/… (kvt_ → 서브키)
끝내기 버튼 / 끝나는 시각 알람 ──▶ 샌드박스 삭제 + 세션·서브키 폐기 (실패하면 5분마다 재시도)
```

- 샌드박스에 들어가는 건 가짜 토큰과 게이트웨이 주소뿐. Daytona 키·OpenRouter 관리 키·미리보기 토큰은 DO(와 실습실 호스트의 30초 캐시) 밖으로 안 나간다.
- 실습실 호스트(`src/labhost.ts`)는 k.shinick.dev 와 출처를 나눴다 — 샌드박스 안 코드가 금고·관리 화면에 닿지 않게. 입장 호스트(`LAB_ORIGIN`, lab.)는 화면만(초대 `/j/`, 깨우기), 권한 쿠키가 없다. 자리마다 자리 호스트 `s-<label>.<LAB_SEAT_DOMAIN>`(label = 코드와 무관한 130비트 난수)가 따로 출처라 다른 자리의 쿠키·화면에 닿지 않는다. 쿠키 `__Host-lab_seat` 는 GET 으로 안 굽고, 입장 호스트에서 온 POST(정확한 Origin·same-site)에 코드의 label 이 호스트와 같을 때만. 자리 호스트는 다른 사이트·다른 자리에서 온 요청은 문서 이동만, Origin 이 있으면 정확히 그 호스트(WebSocket 필수)이고, upstream 의 Domain·우리 쿠키 이름·Clear-Site-Data 는 버린다. `/__lab` POST 는 JSON(입장은 폼)·정확한 Origin·본문 1KiB(SDP answer 128KiB). **`LAB_SEAT_DOMAIN` 은 일부러 비워 둠** — `*.shinick.dev` DNS·route(그리고 console.shinick.dev 등 기존 호스트 제외)를 확인한 뒤에만 켠다 (`wrangler.jsonc` 주석).
- Daytona Tier 1·2 샌드박스는 허용 목록 도메인에만 나갈 수 있다. `k.shinick.dev` 는 막히고 `*.workers.dev` 는 열려 있어서 `workers_dev: true` 로 켜고, 그 호스트에서는 `/p/` 만 응답한다.
- 수업 자료: GitHub 저장소는 샌드박스 안에서 `git clone --depth 1`, ZIP·구글 드라이브 공유 링크는 게이트웨이가 받아(50MB 까지) 올리고 압축을 푼다. 자리마다 처음 깨울 때 한 번.
- `lab-status`: 이 자리 서브키의 사용액/한도(게이트웨이 `/key`)와 남은 시간. Claude Code 상태 줄에도 나온다. `lab-doctor`: 게이트웨이·한도·모델(OpenAI·Anthropic 두 경로, 1토큰)·code-server·디스크·메모리 자가 진단.
- VS Code 위 막대(`src/labbar.ts`): 실습실 호스트가 workbench 문서에만 `<script src="/__lab/bar.js">` 를 끼운다(HTMLRewriter, code-server nonce). 남은 시간·사용액, **⬇ 내 작업 받기**(`POST /__lab/export` → 샌드박스 `~/.gw-export/<uuid>`(0700)에서 `~/work` zip: 링크·특수 파일 안 따라감, 읽은 바이트 1GiB·항목 50,000·240초, node_modules·.venv 제외 → 한 번 쓰는 표 → `GET /__lab/export/<표>` 를 그대로 흘려 보냄. 자리마다 하나·60초 쿨다운, 끝·실패·취소·만료·재시작 모두 폴더를 한 번 지움(`exp:`/`expq:` + 알람)), **✋ 손 들기**, 끝나기 10분 전 알림.
- 강사 표(15초마다 갱신): 자리별 이름·상태·사용액/한도·✋(눌러서 내림)·**최근 오류**(프록시가 upstream 4xx·5xx 를 세션에 적어 둠 — 한도 402, 모델 없음 404, 429 …). 입장한 자리 절반 이상(2자리 이상)이 5분 안에 오류면 수업 카드에 전체 경고. **들어가 보기** = 그 자리 VS Code 를 강사 브라우저에서 연다(같은 code-server).

- 게이트웨이 workers.dev 주소는 wrangler 변수 `LAB_GW` 가 기본값. 계정 하위 도메인을 바꾸면 이 값도 바꿔 배포 (진행 중인 수업은 예전 주소를 쓰므로 수업 사이에).
- Daytona 한도: /lab 이 조직 사용량 API 로 실제 한도·남은 양을 보여 준다. Tier 1 은 합계 10 vCPU · 10 GiB · 디스크 30 GiB(가벼움 사양 5명). 더 많거나 멀티 에이전트 사양이면 Tier 2(카드 + $25 충전, 100 vCPU · 200 GiB). 경고 화면은 Tier 3 가 아니어도 실습실 호스트가 헤더로 없앤다.
- 실습실은 쉬는 시간에 꺼지지 않게 수업 시간만큼 켜 두고(autoStop), 꺼지면 바로 삭제(autoDelete 0).
- 스냅샷: `.\lab\snapshot.ps1` — 스냅샷으로 샌드박스를 만들 때는 사양을 따로 못 줘서 사양마다 하나씩 (`gw-lab-v5-1c2g`·`-2c4g`·`-4c8g`). 내용을 바꾸면 이름(버전)을 올린다. 도구 버전은 파일 안. `-Verify` 로 샌드박스 하나 띄워 점검 후 삭제.
  - 다른 사양: `-Specs '<cpu>/<memory GiB>/<disk GiB>'` (0 으로 시작하지 않는 양의 정수만, 여러 개 가능). 예전 세 사양(1/2/5·2/4/5·4/8/10)은 이름이 그대로 `<Name>-<cpu>c<mem>g`, 그 밖은 디스크까지 `<Name>-<cpu>c<mem>g<disk>d`. 만든 이름은 120자까지.
    ```powershell
    .\lab\snapshot.ps1 -Name gw-lab-custom -Specs 2/8/10 -Plan     # 이름·사양만 출력 (키 안 읽음, API 안 부름) → gw-lab-custom-2c8g10d
    .\lab\snapshot.ps1 -Name gw-lab-custom -Specs 2/8/10 -Verify   # 빌드 후 그 스냅샷으로 점검
    ```
    수업을 만들 때 스냅샷 이름 `gw-lab-custom` 과 같은 cpu·memory·disk 를 고른다. 자동 준비는 같은 기본 이름의 `-1c2g` 스냅샷(독립 Dockerfile 로 만든 활성 사전 사양 — 기본 `gw-lab-v5` 는 이미 있음)이 원본으로 있을 때만 되고, 완전히 새 기본 이름이나 바깥 빌드 컨텍스트가 필요한 원본은 위 `snapshot.ps1` 로 한 번 만들어 둔다(이미지·실행 중 샌드박스를 복사하지 않는다). 그 조건이면 미리 안 만들어 둬도 된다: /lab 에서 "직접 입력" 사양으로 **만들기** 를 누르면, 그 사양의 스냅샷이 아직 없을 때 `/api/lab/create` 가 202 `{snapshotPreparing, snapshot, state, retryAfterMs}` 를 돌려주고(수업·자리·샌드박스는 만들지 않음) 서버가 스냅샷을 준비한다. 화면은 그동안 `/api/lab/snapshot`(`x-admin-token`, 누른 순간 고정한 `{snapshot, cpu, memory, disk}`)만 5초마다 묻고, `snapshotReady` 가 오면 처음 고정한 입력 그대로 `/api/lab/create` 를 **딱 한 번** 보낸다. 처음 쓰는 사양은 몇 분 걸릴 수 있고, 같은 사양은 다음부터 바로 쓴다. 처음 202 부터 8분이 지나거나(응답 없는 조회도 그 시각에 끊고, 넘긴 뒤 온 준비됨으로는 만들지 않는다) 오류·로그인 만료·연결 끊김·알아볼 수 없는 응답(이름이 기본 이름·사양에서 나온 것과 다름 포함)이면 화면은 멈추고 오류 문구를 남긴 채 만들기를 다시 켠다 — 이미 접수된 스냅샷 요청은 화면을 닫아도 취소되지 않으니(실패한 빌드는 이어지지 않는다) 잠시 뒤 같은 사양으로 다시 누르면 상태를 다시 확인한다. 수업 만들기 요청은 자동으로 다시 보내지 않는다 (마지막 만들기가 끊기면 목록만 다시 불러온다). 스냅샷 요청은 만들기를 눌렀을 때만 간다 (화면 열기·입력 변경·새로고침·링크로는 안 감). 회귀: `node test/lab-snapshot-auto-ui.mjs`. 이름·사양이 잘못됐거나 같은 이름의 기존 스냅샷이 사양이 다르면(-Force 여도) 아무것도 지우거나 만들지 않고 멈춘다. 실제로 쓸 수 있는 최댓값은 조직 한도이고 Daytona 가 거부한다.

## 참여자 화면 벽과 탭 지원

참여자가 실습실에 입장하면 편집기·터미널 화면이 모임지기 `/lab` 의 **모임 화면**에 자동으로 나타난다. 참여자가 공유 버튼이나 브라우저의 화면 선택 창을 누를 필요가 없다. 개인 PC의 다른 창은 포함하지 않는다. 약 3초 간격의 미리보기이며 동시에 보는 영상은 8개까지이고, 영상 보기를 멈추거나 다시 열고 크게 볼 수 있다. **제어 요청** 뒤 참여자가 **5분 동안 제어 허용**을 누른 현재 실습실 탭에서만 클릭·키보드가 들어간다. 어느 쪽이든 끝내거나, 거절·철회·만료되면 새 입력은 멈춘다. 자동 미리보기는 계속된다.

보안 키로 `/lab` 을 열면 일반 관리(페이지 메모리, 8시간)와 따로 고정 8시간의 화면 세션이 만들어진다. 참여자 탭 닫기와 모임 종료·만료 시 송출을 정리한다. 모임지기 로그아웃은 그 기기의 영상 수신과 제어를 끝낸다. 관리 세션이 만료되면 수업 카드의 만들기·초대·끝내기 같은 버튼은 걷히지만, 모임 화면의 공유 버튼은 남는다. 보고된 영상 끊김과 관리 만료가 같은 원인인지는 아직 확인되지 않았다. 순서·입력 한계·확인 절차는 [참여자 화면과 탭 지원](docs/lab-live-support.md).

## 선택한 자리의 수업 터미널 함께 실행

모임지기 `/lab` 수업 카드의 **수업 터미널 함께 실행**에서 자리를 선택하고 시작한다. **명령 보내기**를 누르면 선택한 자리 각각의 전용 `gw-lesson` tmux에 같은 한 줄과 Enter를 보낸다. 개인 터미널은 별도로 유지한다.

- 참여자는 실습실 막대의 **수업 터미널** 안내에서 연결 명령을 복사한다: `tmux -u attach -r -t gw-lesson`. 새 스냅샷에는 **수업 따라보기 (모임지기와 함께 보기)** 프로필도 있다. 개인 실습으로 돌아갈 때는 새 bash 터미널을 연다.
- 입력은 수업 터미널의 현재 프로그램(셸·OpenCode 등)으로 전달된다. 먼저 `pwd` 같은 셸 명령으로 확인하고, `opencode`가 열린 뒤에만 자연어 요청을 보낸다. 자리별 전송 확인은 과제 완료나 결과 정확성 판정이 아니다.
- 새로 인증한 관리 세션은 **이 관리 세션에서 이어받기**로 기존 세션과 요청 ID를 유지한다. 읽기 전용 모니터 쿠키나 참여자 쿠키에는 명령 권한이 없다.
- 같은 요청 ID는 응답이 유실돼도 자동 재실행하지 않는다. 결과 확인이 필요하면 해당 자리 터미널을 확인한다. 전송 중 **새 명령 전송 중지**는 이후 전달을 멈추며 이미 실행 중인 프로그램을 종료하지 않는다.
- 일반 명령 전달은 한 줄 최대 4,096자다. 실시간 키 입력 복제, 여러 줄·TAB 등 임의 특수키 전달은 지원하지 않는다. Ctrl+C는 아래의 별도 프로그램 중단 요청에서만 전달한다. 준비 중에는 시작 결과를 받은 뒤 중지할 수 있다.

로컬 검증: `npm run check`, `node test/lab-terminal-service.mjs`, `node test/lab-terminal-state.mjs`, `node test/lab-terminal-native.mjs`, `node test/lab-terminal-ui.mjs`, `node test/lab-terminal-visual.mjs`. native 검증은 격리된 로컬 WSL tmux를 쓰며 실제 참여자 자리에는 명령을 보내지 않는다.

## 수업 비상 제어: 0단계 — 명령 전달 일시정지

모임지기 `/lab` 진행 화면의 모아보기 위에 있는 **명령 전달 일시정지**는 새 수업 터미널 준비와 명령 전달을 서버에서 차단한다. 준비·전송 요청이 기다리는 동안에도 누를 수 있다. 이미 외부에 전달된 명령, 참여자가 직접 실행한 프로그램과 개인 터미널은 종료하지 않는다.

- 상태는 서버에 저장되며 새로고침·관리 재인증·터미널 이어받기로 풀리지 않는다. **명령 전달 재개**를 명시적으로 선택해야 새 명령을 보낼 수 있다. 재개해도 이전 전달 작업의 남은 자리를 자동으로 실행하지 않는다.
- 다른 탭의 오래된 재개 요청은 상태 번호가 달라 거부된다. 이미 일시정지 상태여도 새로운 일시정지는 이전 재개 요청을 막는다. 같은 요청의 재확인은 같은 ID를 유지한다.
- 응답을 잃으면 **같은 일시정지/재개 요청 다시 확인** 또는 **전달 상태 확인**을 사용한다. 확인되지 않은 상태에서는 화면에서 새 전달을 허용하지 않는다. `보냄`은 프로그램 완료나 결과 정확성을 뜻하지 않는다.
- 새 준비·전달 요청은 화면에서 확인한 서버 상태 번호도 고정해 보낸다. 서버 처리가 늦어 일시정지·재개 뒤 도착한 이전 요청도 거부한다. 상태 번호가 없는 예전 화면에서는 새 명령을 보내지 않으므로 배포 후 화면을 새로고침한다. 이미 기록된 요청 결과 확인은 계속 허용한다.
- 제어 응답을 8초 안에 받지 못하면 결과 확인 필요로 표시하고 같은 요청을 다시 확인할 수 있다. 시간 초과는 서버 실행 취소를 뜻하지 않는다.
- 기존 **새 명령 전송 중지**는 해당 수업 터미널 제어 세션을 닫는 별도 기능이다. **명령 전달 일시정지**는 수업 전체의 전달 허용 상태를 보존하는 기능이다.
- 내부 제어 동작 기록은 수업당 128건까지 보존한다. 한도 초과 시 명시적 오류를 표시하며 기존 터미널 전송 중지와 수업 종료는 계속 사용할 수 있다. 프로그램 중단·파일 보존·자리 교체는 아래 별도 제어에서 다룬다.

검증: `node test/lab-control-service.mjs`, `node test/lab-control-state.mjs`, `node test/lab-control-ui.mjs`. State 검증은 실제 서버 클래스를 가짜 외부 실행기에 연결하여 권한 취소·전달 도중 일시정지·재개·종료 경합을 재현한다. 브라우저 검증은 가짜 요청만 사용하는 Edge에서 응답 유실·늦은 응답·다른 탭의 상태 번호 충돌을 검사한다.

## 수업 비상 제어: 1단계 — 시험용 실습실과 전달 미리보기

참여자가 들어오기 전, 본 실습실과 같은 설정으로 **1인 실습실**을 별도로 만든다. 본 수업 카드의 **시험용 실습실**에서 그 실습실을 지정한다. 샌드박스·모델·자료·공유 설정이 같고, 입장·이름·터미널 사용 이력이 없는 자리만 지정할 수 있다. 지정한 실습실은 참여자 초대를 받지 않으며 읽기 전용 참여자 모니터에서도 제외한다. 본 수업을 끝내면 함께 정리한다. 이미 사용 중인 참여자 자리를 시험 자리로 가져오지 않는다.

1. 시험용 실습실에서 한 줄 명령을 실행하고 출력을 직접 확인한다. `전달됨`은 입력 전달이 확인됐다는 뜻이다. OpenCode의 응답 완료와 결과 정확성은 직접 판단한다. 본 수업의 전달이 일시정지 상태여도 시험 실행은 가능하다.
2. 본 수업의 수업 터미널에서 명령 보내기를 선택하면 **명령 원문과 대상 자리 번호**를 다시 확인한다. 일치하는 시험 전달 기록이 없다면 시험을 생략한다는 항목을 직접 선택해야 한다.
3. 마지막 확인 버튼을 눌러야 참여자 실습실에 전달한다. 확인 도중 일시정지·세션 변경·자리 교체·실습 설정 변경이 발생하면 다시 확인한다. 시험 실행이나 전달 재개 자체가 참여자 명령을 자동 실행하지 않는다.

- 미리보기는 5분 동안 유효하고 한 전달 작업에만 사용한다. 응답이 유실된 작업의 같은 ID 재확인은 새 실행을 만들지 않는다. 결과를 모르는 요청에는 자동 재시도를 하지 않는다.
- 통신 확인은 8초 뒤 다시 조작할 수 있다. 시간 초과가 서버 작업 취소를 뜻하지는 않는다. 미확인 시험 요청은 출력을 확인한 뒤 **요청 기록만 정리**할 수 있으며, 이 동작은 프로그램을 중단하거나 새 명령을 실행하지 않는다. 배포 전에 열어 둔 관리 화면은 새로고침하여 미리보기 기능을 받는다.
- 시험 전달·미리보기 기록에는 명령 해시와 식별 정보만 저장한다. 명령 원문·출력·파일·관리 토큰은 저장하지 않는다. 시험 출력은 관리자 요청 시 최근 부분만 읽으며 기본적인 키 형식을 가린다.
- 수업당 미리보기 256건, 시험 실행 100건, 시험 연결 요청 128건까지 보존한다. 한도 도달 시 명시적 오류를 표시한다. 시험용 실습실은 별도 샌드박스와 사용료를 사용하므로 필요할 때 한 자리만 준비한다.

검증: `node test/lab-preview-service.mjs`, `node test/lab-trial-service.mjs`, `node test/lab-trial-state.mjs`, `node test/lab-trial-ui.mjs`, `node test/lab-trial-panel-ui.mjs`. 실제 참여자 실습실에 명령을 보내는 시험은 포함하지 않는다.

## 수업 비상 제어: 2단계 — 참여자 상태판

참여자별 연결 신호·도움 요청·서버 준비 상태에 **마지막 명령 전달 상태와 기록 시각**을 함께 표시한다. 이는 현재 수업 터미널의 마지막 입력 기록이며 AI 작업의 완료 판정이 아니다. 서버가 재시작된 뒤 전달 중이던 기록은 **결과 확인 필요**로 표시하고 다시 실행하지 않는다. 기록이 없거나 시각을 신뢰할 수 없으면 **확인 안 됨**, 5분이 지난 기록에는 **오래된 기록**을 표시한다.

수업 카드에는 서버 시계를 기준으로 남은 시간을 표시한다. 읽기 전용 모니터에서도 상태와 기록 시각을 볼 수 있으며, 명령 원문·출력·요청 ID·샌드박스 정보는 포함하지 않는다. 상태판을 읽는 과정에서는 외부 실행이나 공급자 호출을 추가하지 않는다.

검증: `node test/lab-terminal-service.mjs`, `node test/lab-delivery-state.mjs`, `node test/lab-readiness-ui.mjs`, `node test/lab-teacher-monitor.mjs`.

## 수업 비상 제어: 3단계 — 수업 터미널 프로그램 중단 요청

**명령 전달 일시정지** 후 수업 카드의 **수업 터미널 프로그램 중단 요청**을 연다. **대상 다시 확인**에서 자리를 직접 고르고 **선택한 자리의 실행 프로그램 확인**을 누른다. 대상 자리 번호와 실행 프로그램을 확인한 뒤 마지막 **중단 요청 보내기**를 눌러야 Ctrl+C를 전달한다. 전송 세션을 닫은 뒤에도 현재 수업 터미널이면 사용할 수 있다. 관리 재인증 후에는 기존 수업 터미널을 명시적으로 이어받는다.

- 대상은 `gw-lesson`의 정확한 첫 창·첫 pane이다. 개인 터미널과 샌드박스 전체를 종료하거나 삭제하지 않는다. 일반 임의 입력·프로세스 강제 종료 기능을 제공하지 않는다.
- 확인은 60초 유효하며 한 요청에만 사용한다. 서버가 관리 권한·현재 수업 터미널·자리와 샌드박스·실습 설정·일시정지 상태 번호를 실행 직전 다시 확인한다. tmux 서버·pane·전경 프로세스의 식별과 시작 시각이 달라지면 입력을 전달하지 않는다. 같은 이름의 새 프로그램도 이전 확인으로 중단 요청하지 않는다.
- 응답 유실·시간 초과·서버 재시작은 자동 재전송하지 않는다. **같은 중단 요청 결과 다시 확인**은 같은 ID의 기록을 읽는다. 결과를 모르면 자리에서 실행 상태를 직접 확인하고 **확인 중인 요청 기록 정리**로 화면 기록만 정리한다.
- `Ctrl+C 전달됨`은 입력 전달 결과이며 프로그램 종료·저장 완료를 보장하지 않는다. 프로그램이 Ctrl+C를 처리하지 않거나 입력 이후 상태가 바뀔 수 있다. 이미 외부에 전달된 입력은 나중의 일시정지·권한 취소로 회수할 수 없다. 새 명령 전달 재개도 별도로 선택해야 한다.
- 수업당 프로그램 확인 128건, 중단 요청 100건까지 기록한다. 실행 프로그램의 짧은 이름과 내부 대상 증명만 저장하며 터미널 출력·명령 인자·파일 내용·관리 토큰은 저장하지 않는다. 읽기 전용 참여자 모니터에는 실행 권한을 주지 않는다.

검증: `node test/lab-interrupt-service.mjs`, `node test/lab-interrupt-state.mjs`, `node test/lab-interrupt-ui.mjs`. 실제 tmux 검증은 WSL Ubuntu의 Node 경로를 `LAB_TEST_LINUX_NODE`로 지정한 뒤 `node test/lab-interrupt-native.mjs`로 실행한다. 독립 소켓·임시 HOME을 사용하며 실제 참여자 실습실에 연결하지 않는다.

## 수업 비상 제어: 4단계 — 파일 체크포인트와 ZIP 직접 확인

모임지기는 명령 전달을 일시정지하고 **파일 체크포인트**에서 대상·기록을 확인한다. 참여자에게 편집기 파일 저장을 안내한 뒤 자리를 직접 고르고, 보관 범위를 확인한 다음 별도로 만들기를 누른다. 수업 터미널을 시작하지 않았어도 사용할 수 있다. 원본 work 파일을 덮어쓰지 않고 샌드박스 안의 새 폴더에 ZIP을 만든다. 수정 중인 파일은 시점이 섞일 수 있으며 저장하지 않은 편집기 내용과 프로그램 실행 상태는 포함하지 않는다.

- 파일 읽기 64 MiB·항목 4,000개·30초 범위이며 링크·제외 폴더를 건너뛴다. ZIP 자체에는 압축·목록 정보의 용량 여유를 따로 적용한다. 결과에는 제외 개수를 표시한다. 자리의 정확한 코드·샌드박스 신원마다 최대 5회, 모임당 최대 64회 요청을 기록하며 불확실·건너뜀 기록도 한도에 포함한다.
- 폴더 만들기·압축 도구 올리기·ZIP 실행의 각 외부 동작 직전에 관리 권한·전체 대상·일시정지 상태를 다시 확인한다. 도중에 바뀌면 이후 동작과 남은 자리를 차단한다. 이미 받아들여진 외부 작업의 취소나 완성 상태는 보장하지 않는다. 응답 유실·서버 재시작 뒤 같은 요청 결과 확인은 새 ZIP을 만들지 않는다.
- **실습실 안에 보관**은 외부 백업 완료를 뜻하지 않는다. 참여자는 **파일 보존 확인 → 이전 체크포인트 내려받기**에서 자기 현재 자리의 사용 가능한 보관본만 선택할 수 있다. 보관본을 내려받아도 샌드박스 안의 원래 ZIP은 지우지 않는다. 일반 **내 작업 받기**는 현재 work 파일을 새로 묶는다.
- 서버가 알린 바이트를 모두 전달한 기록과 참여자의 **ZIP을 직접 열어 필요한 파일을 확인했음** 표시는 별개다. 버튼·링크 클릭, 중간 취소, 잘린 전송, 크기 불일치만으로 완료나 직접 확인을 표시하지 않는다. 직접 확인 표시는 사람이 보고 남긴 기록이며 PC 저장 상태나 ZIP 내용의 자동 검증이 아니다. 새 다운로드 전송이 완료되면 이전 직접 확인 표시를 초기화한다.
- 모임지기 자리 표에 전송·직접 확인 시각을 표시하고 수업 종료 확인창에서 미확인 자리 수를 안내한다. 표시 시각 이후 수정한 파일은 별도로 저장하고 다시 내려받아야 한다. 참여자 막대는 서버 시계를 기준으로 종료 10분 전, 미확인 상태에서 5분 전, 모든 참여자에게 1분 전 저장 안내를 한다. 안내나 직접 확인 표시는 자동 종료 시각을 연장하지 않는다.
- 내부 체크포인트도 모임 종료·만료 시 함께 삭제된다. 외부 보존은 참여자가 자기 PC에 ZIP을 저장하고 내용을 확인해야 한다. 화면의 **요청 표시 정리**는 서버 작업 취소나 보관본 삭제가 아니다. 자동 복원·원본 덮어쓰기를 수행하지 않는다.

검증: `node test/lab-checkpoint-service.mjs`, `node test/lab-checkpoint-state.mjs`, `node test/lab-checkpoint-api.mjs`, `node test/lab-file-preservation.mjs`, `node test/lab-checkpoint-ui.mjs`, `node test/lab-files-ui.mjs`, `node test/lab-bar-recovery-ui.mjs`. 실제 파일·ZIP 검증은 WSL Node 경로를 `LAB_TEST_LINUX_NODE`로 지정하고 `node test/lab-checkpoint-native.mjs`로 실행한다. 독립 임시 폴더와 가짜 전송을 사용하며 실제 참여자 파일에 접근하지 않는다.

## 수업 비상 제어: 5단계 — 자리 연결 복구와 실습실 교체

명령 전달을 일시정지하고 **자리 연결 복구 · 실습실 교체**에서 자리 하나를 선택한다. 대상·파일 상태를 새로 확인하고 실행 범위를 확인한 뒤 마지막 확인란과 실행 버튼을 사용한다.

- **기존 연결 복구**는 기존 샌드박스의 편집기 연결을 확인하고, 필요하면 실습실과 `lab-start`를 한 번 켠다. 자료 재설치·파일 덮어쓰기·개인 터미널 종료를 하지 않는다. 연결 확인 성공은 자료나 실행 프로그램 복구 완료를 뜻하지 않는다. 기존 준비 작업이 진행 중이면 먼저 그 결과를 확인한다.
- **새 실습실 교체**는 기존 세션 ID·실제 예산 키·사용량·공유 호출 수·진행 중 호출·한도·종료 시각을 유지한다. 새로운 예산 키를 발급하거나 사용량을 초기화하지 않는다. 기존 예산 세션이나 공급자 승인을 확인할 수 없으면 교체를 차단한다. 새 실습실의 자원 비용은 추가된다.
- 교체에는 현재 자리의 ZIP 전송 후 참여자가 직접 열어 확인한 기록이 필요하다. 파일을 확보하지 못한 경우에는 참여자와 손실 가능성을 확인하는 별도 동의란을 직접 선택한다. 새 전송으로 확인 기록이 바뀌면 실행 직전에도 차단한다. 확인 이후 수정한 파일까지 보장하지 않는다.
- 새 자리 코드·호스트·접속 토큰을 적용하며 예전 토큰과 초대 링크는 이후 요청에서 사용할 수 없다. 이미 열린 연결·이미 공급자가 받아들인 호출은 즉시 회수할 수 없다. 호스트 캐시로 이전 연결이 잠시 남으면 약 30초 뒤 새 링크로 다시 연다. 모임지기는 새 초대 링크를 전달하고 수업 터미널 대상을 다시 선택한다. 명령 전달은 일시정지로 남으며 직접 재개해야 한다.
- 원래 샌드박스와 파일은 모임 종료까지 남긴다. 새 실습실로 파일을 자동 복사하거나 원본을 지우지 않는다. 교체 완료는 새 자리 연결을 적용했다는 뜻이며, 참여자 입장 후 새 실습실 준비·파일 옮기기는 별도로 확인한다. 모임 종료·만료 시에는 같은 모임의 원래 실습실과 새 실습실을 모두 정리한다.
- 요청을 먼저 영속화하고 외부 동작마다 권한·자리 신원·일시정지 개정 번호를 재확인한다. 응답 유실·서버 재시작 후 **같은 복구 요청 결과 다시 확인**은 새 실습실을 또 만들지 않는다. 결과가 불분명하면 자리를 잠근다. 확인된 미연결 새 자원은 정리 대기에 남기며, 생성 응답의 ID조차 모르면 추측해서 삭제하지 않는다.
- 잠금 해제 전에는 Daytona에서 원래 실습실을 직접 점검한다. 교체 요청이면 요청 ID의 `gw-recovery` 라벨 자원도 확인하고, 연결 복구 요청이면 기존 편집기와 기동 요청 상태를 확인한다. **복구 대상·파일 상태 확인**으로 현재 자리를 다시 읽고 점검 확인란을 선택한 뒤 잠금을 해제한다. 진행 중인 요청의 잠금은 풀 수 없다. 잠금 해제는 다음 새 요청을 허용할 뿐 앞 요청 취소·자원 삭제를 하지 않는다. 불확실한 외부 생성 결과를 완전히 되돌릴 수 있다고 보장하지 않는다. 모임당 복구 요청은 최대 64건이다.

검증: `node test/lab-seat-recovery-service.mjs`, `node test/lab-seat-recovery-state.mjs`, `node test/lab-seat-recovery-api.mjs`, `node test/lab-seat-recovery-ui.mjs`. 합성 저장소와 차단된 공급자 네트워크, 브라우저 fixture를 사용하며 실제 참여자 자리에서 복구를 실행하지 않는다.

## 수업 비상 제어: 6단계 — 모의훈련과 운영 대응

모임 전 더미 실습실·가짜 파일로 진행할 점검 순서와 상황별 대응은 [비상 대응표](docs/classroom-emergency-playbook.md)를 따른다. 자동 검증은 `node tools/test-classroom-emergency.mjs`, 기존 전달·시험 실행·중단·파일·목록·모니터까지 함께 확인하려면 `node tools/test-classroom-emergency.mjs --full`로 실행한다. 실패한 스크립트가 있으면 즉시 중단하고 해당 실패를 표시한다.

자동 모의훈련은 합성 저장소·차단된 공급자·브라우저 fixture를 사용한다. 실제 workerd·SQLite 검증은 별도 로컬 프로세스에서 교체 중 사용량 변경, 토큰 교체, 동일 요청 재조회, 재시작 후 한도 보존을 확인한다. 이 테스트가 만든 `gw-recovery-sqlite-*` 임시 폴더에는 합성 데이터만 남겨 조사 증거로 보관한다. 실제 참여자 실습실, 실제 공급자 생성·과금·알림, 설치된 PWA의 수동 조작 완료를 증명하는 검증은 아니다.

## 모임별 조교 권한과 도움 요청

모임지기 화면의 **조교 권한**에서 모임·자리·행동·만료를 정해 연결 코드를 발급한다. 조교는 `/lab/assistant`에서 연결하고 참여자는 실습실 안의 **도움 요청**으로 질문·답변·본인 해결 확인을 이어간다. 기본 범위는 상태와 질문·답변이며, 승인된 요청문 전달과 새 전달 일시정지는 별도로 선택한다. 관리자 토큰이나 공급자 키를 넘기지 않는다.

발급한 연결 코드는 한 번만 표시하고 저장소에는 해시만 둔다. 모임지기가 회수하거나 권한·모임이 만료되면 이전 요청의 재조회도 거부한다. 조교의 답변은 해결 확인이 아니며, 보관 확인·손실 동의·복구·교체·종료·재개·자유 명령 실행은 위임하지 않는다. 서버에 AI 모델이나 Discord 연결을 추가하지 않으며 Grok Bot이 허용된 조교 화면 또는 API를 사용한다.

준비·권한 범위·실제 연결 시험은 [조교 운영 가이드](docs/classroom-assistants.md)를 따른다. 모임 단계 자동 전환과 음성 진행은 이 버전에 포함하지 않는다.

## 배포는 사용자가 직접

```powershell
.\deploy.ps1 -SkipSetup   # 코드 배포 + MASTER_KEY(없을 때만 생성) + 예전 공급자 secrets 삭제
.\kv.ps1 push             # 공급자 키 올리기
.\deploy.ps1 -CodeOnly    # 코드만
.\deploy.ps1 -SetupOnly   # 보안 키 추가 등록용 SETUP_TOKEN 발급 → 끝나면 -RemoveSetup
```

`MASTER_KEY` 는 한 번 만들면 다시 만들지 않는다. 잃어버리면(지우면) 저장된 공급자 키를 못 풀므로 `kv.ps1 push` 로 다시 올리면 된다.
`k.shinick.dev` 는 Cloudflare Access 뒤에 두지 않는다 (API 클라이언트가 직접 부른다).
