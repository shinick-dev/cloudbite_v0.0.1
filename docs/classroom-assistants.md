# 모임 조교 권한과 도움 요청

모임지기는 한 모임의 특정 자리와 행동만 맡기는 조교 연결 코드를 발급합니다. 조교는 /lab/assistant 화면 또는 x-lab-assistant 헤더로 인증하는 API를 사용합니다. 참여자는 자기 실습실의 도움 요청에서 질문하고 답변을 읽습니다. AI 모델이나 Discord 연결은 서버에 내장하지 않습니다. Grok Bot이 조교 화면을 읽고 안내를 작성합니다.

## 모임지기가 준비하는 순서

1. /lab에 보안 키로 로그인하고 해당 모임 카드의 조교 권한을 엽니다.
2. 자리와 허용 행동, 만료 시간, 조교 이름을 확인합니다. 기본 범위는 상태 조회와 질문 읽기·답변입니다.
3. 요청문 전달을 맡길 때만 해당 권한을 켜고 미리 승인할 제목·본문을 작성합니다. 조교는 승인된 ID의 원문만 한 자리에 전달할 수 있습니다. 이 동작은 실행 명령이 아닙니다.
4. 새 전달 일시정지를 맡기려면 모든 정상 자리를 선택합니다. 이 동작은 모임 전체의 새 전달을 막으며 실행 중인 프로그램을 멈추지 않습니다. 재개는 모임지기가 합니다.
5. 발급 응답의 연결 코드는 한 번만 표시됩니다. 일반 대화·URL·화면공유에 넣지 않습니다. Grok의 클라우드 브라우저에서 /lab/assistant를 열게 하고 Take control로 직접 입력합니다.
6. 권한 목록에서 대상·만료와 사용 기록을 확인합니다. 필요하면 회수합니다. 회수·만료된 자격으로는 이전 요청의 성공 결과도 다시 받아 실행할 수 없습니다.

발급 응답을 잃으면 목록에서 생성 여부를 먼저 확인하고 불명확한 권한을 회수한 뒤 새 코드를 발급합니다. 발급 요청을 자동 반복하지 않습니다. 조교 화면의 로그아웃은 해당 브라우저 쿠키를 지우며, 연결 코드 자체를 폐기하려면 모임지기 화면에서 회수합니다.

## 권한 범위

| 권한 | 허용 동작 |
|---|---|
| status:read | 지정 모임·자리의 제한된 상태 조회 |
| help:read | 지정 자리의 질문과 조교 안내 읽기 |
| help:reply | 열린 질문에 최종 답변 하나 작성 |
| template:send | 발급 때 승인한 요청문을 지정 자리의 안내로 전달 |
| control:pause | 모든 정상 자리의 권한이 있을 때 새 전달 일시정지 |

다른 모임, 허용하지 않은 자리, 임의 요청문·셸 실행, 재개·Ctrl+C·복구·교체·종료, 공급자 키·예산·파일 조작은 이 권한으로 열리지 않습니다. 읽기 전용 상태는 참여자의 터미널과 파일 내용을 포함하지 않습니다.

## 참여자와 조교의 흐름

참여자가 도움 요청을 제출하면 접수 상태가 됩니다. 조교 답변은 답변 도착이며 해결과 다릅니다. 참여자가 답변을 확인한 뒤 해결 확인을 직접 눌러야 해결 상태가 됩니다. 조교가 참여자를 대신해 해결이나 파일 보관을 확인하지 않습니다.

참여자가 자리 교체로 새 연결을 받으면 예전 자리 코드에 속한 질문·안내는 자동으로 새 자리 쿠키에 노출되지 않습니다. 조교 권한의 자리 번호 범위는 유지되지만 상태는 새로 읽어야 합니다.

## 무인 운영 전에 확인할 것

역할 프롬프트, 실습실 권한, Grok Auto-review 규칙은 서로 다릅니다. 다음 조건이 모두 필요합니다.

- Bot이 오늘의 원본과 비상 매뉴얼을 읽었다.
- 지정 모임의 조교 화면에 실제로 로그인했다.
- 더미 참여자의 질문 수신·답변·본인 해결 확인을 왕복 시험했다.
- 승인된 요청문은 해당 자리만 받았으며 실행되지 않았다.
- 일시정지는 새 전달만 막고 재개는 수행하지 않았다.
- 다른 모임·자리·행동과 회수·만료 자격은 거절됐다.
- Bot이 화면에서 읽은 시각과 실제 확인한 결과를 구분했다.

웹페이지는 수신함 역할을 합니다. Bot이 페이지를 열었다는 것만으로 백그라운드 감시와 즉시 응답을 보장하지 않습니다. Grok에서 실제 동작 방식과 종료 시간을 시험해야 합니다. 루틴 간격과 앱 종료 후 동작 여부도 별도 확인합니다.

## 자동 진행으로 확장할 때

현재 버전은 질문·답변과 제한된 조치를 맡기는 기반입니다. 모임의 단계 자동 전환과 음성 진행은 포함하지 않습니다.

첫 운영에서는 진행 조교가 현재 단계와 남은 질문을 요약하고, 모임지기가 다음 단계로 전환합니다. 완료 기준은 접속·입력이 아니라 참여자의 원본 대조와 외부 파일 열기 확인입니다. 이후 단계 전환 조건, 진행 시간 상한, 지연 자리의 별도 지원, 장애 시 정지 조건을 정해 자동 진행을 확장할 수 있습니다.

## HTTP 연결

모든 경로는 운영 ORIGIN의 POST JSON입니다. 브라우저는 정확한 같은 Origin과 HttpOnly 쿠키를 사용합니다. 직접 HTTP 클라이언트는 x-lab-assistant 헤더에 연결 코드를 넣습니다. 토큰을 URL·본문 로그·일반 채팅에 넣지 않습니다.

조교 경로:
- /api/lab/assistant/session: 브라우저 연결 코드 입력
- /api/lab/assistant/status: 빈 본문, 현재 권한과 지정 모임 상태
- /api/lab/assistant/questions: {id}
- /api/lab/assistant/reply: {id,requestId,questionId,text}
- /api/lab/assistant/template: {id,requestId,templateId,n}
- /api/lab/assistant/pause: {id,requestId,reason}
- /api/lab/assistant/logout: 빈 본문, 브라우저 쿠키 해제

쓰기 requestId는 UUIDv4입니다. 응답 불명 시 같은 ID와 같은 본문으로만 결과를 다시 확인합니다. 다른 본문에 같은 ID를 쓰면 거절합니다. 자동으로 새 ID를 만들어 다시 보내지 않습니다.

## 검증 범위

`node tools/test-classroom-assistants.mjs`로 서비스·독립 경계 검사·HTTP 인증·화면·실제 로컬 Worker와 SQLite를 함께 확인합니다.

자동 테스트는 합성 모임·참여자·권한과 로컬 런타임을 사용합니다. 실제 Grok Bot 접속·유료 샌드박스·참여자 파일·실제 질문의 운영 성공은 별도 더미 모임 시험으로 확인합니다.

## AI 조교 봇 (classroom-ta-agent)

`classroom-ta-agent/`에 조교 역할을 맡는 파이썬 봇이 있습니다. 이 문서의 외부 봇 자리에서 x-lab-assistant 헤더로 인증하고 status:read·help:read·help:reply만 사용합니다. 요청문 전달과 일시정지는 호출하지 않습니다. 질문은 페르소나와 가드레일을 거쳐 OpenRouter 모델로 답하고, 답변은 requestId를 먼저 저장한 뒤 한 번만 보냅니다. 응답을 모르면 같은 ID와 같은 본문으로만 다시 확인합니다. 위기 신호가 보이는 질문은 답하지 않고 열어 둡니다. 모임이 일시정지 상태이면 답하지 않습니다. 실행 방법과 한계는 `classroom-ta-agent/README.md`를 참고하세요. 무인 운영 전 더미 모임 왕복 시험은 그대로 필요합니다.
