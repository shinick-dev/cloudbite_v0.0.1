# 모임지기 중앙 작업 공간 설계

2026-10-16 UI/UX 검수 후 사용자 선택을 반영한 설계안. 구현·검증을 마치고 v2026.10.16.19에 반영했다. 실제 사용법과 범위는 [운영 가이드](classroom-unified-workspace.md)를 따른다.

## 목적과 확정 방향

모임지기는 설명하며 실습하고, 참여자 흐름을 관찰하며, 도움 요청에 바로 대응한다. 중앙의 실제 작업 화면과 참여자에게 송출하는 화면을 하나의 시연 공간으로 경험하게 한다. 별도의 작업/송출 미리보기 선택을 기본 동선에서 없앤다.

- 기본 중앙은 **내 시연**: 직접 편집·터미널 작업하는 영역이 송출 원본이다. 읽기 전용 캡처 영상을 실제 편집기처럼 오인하게 만들지 않는다. 송출 시작·중지와 실제 캡처/송출 상태를 짧게 표시한다.
- 버튼 하나로 **참여자 모아보기 ↔ 내 시연**을 전환한다. 별도 페이지·탭 없이 중앙 영역을 교체한다. 화면 크기·전체 화면 조작은 해당 영역의 작은 도구로 제공한다.
- 새 도움 요청은 해당 참여자 화면을 중앙에 자동 표시한다. 헤더에 **입장 아이디 · 좌석번호 · 도움 요청 상태**를 함께 표시한다. 예: `My choice · 3번 좌석 · 도움 요청`. 입장자가 입력한 표시 이름을 검증된 외부 계정 ID라고 주장하지 않는다.
- 지원을 마치면 직전의 내 시연 또는 모아보기로 돌아온다. 시연 초안·파일·터미널과 송출을 유지한다.
- 화면 관찰은 자동으로 진행하되 클릭·키보드 제어는 기존의 참여자 별도 허용을 유지한다. 새 요청으로 기존 제어 대상을 자동 교체하지 않는다.

## 중앙에서 보는 화면과 전체 송출의 관계

사용자에게 작업 화면과 송출 화면은 하나의 개념이다. 구현에서는 전체 모임에 나가는 **시연 원본**과 모임지기만 보는 **운영 화면**의 경계를 유지한다. 지원/모아보기로 전환해도 참여자들에게 다른 사람 화면이나 관리 UI가 자동 송출되지 않게 한다.

현재 구현은 getDisplayMedia로 선택한 화면을 송출하고 같은 스트림을 중앙 영상으로 재생한다. 따라서 버튼 이름을 합치는 것만으로는 이 요구를 충족하지 않는다. 관리 탭 전체를 캡처하는 방식에 의존하지 않는 시연 전용 원본을 구현·검증해야 한다. 시연 영역 캡처 또는 분리된 시연 표면 중 실제 편집·터미널 지원과 캡처 품질을 충족하는 방식을 선택한다. 현재 HTML의 textarea만 그려 전체 실습실 지원이 끝났다고 간주하지 않는다.

## 자동 지원 전환의 세부 동작

- 모임 선택 후 처음 읽은 기존 손들기 상태와 새 요청을 구분한다. 새로고침·반복 폴링마다 같은 사람 화면을 다시 열지 않는다.
- 도움 요청은 현재 선택한 모임 범위로 제한한다. 같은 좌석의 요청 갱신과 요청 해제를 반영한다.
- 요청이 여럿이면 순서대로 대기시키고 아이디·좌석번호·대기 수를 표시한다. 이미 돕는 사람을 새 요청마다 강제로 교체하지 않는다.
- 중앙 화면이 자동으로 바뀌어도 입력 중인 키보드 이벤트를 참여자 제어로 넘기거나, 입력 포커스를 빼앗아 실수로 다른 터미널에 타이핑하게 하지 않는다.
- 영상이 아직 없으면 같은 아이디·좌석번호와 연결 대기 상태를 표시한다. 과거 프레임을 현재 화면으로 표현하지 않는다.
- 지원 종료 시 기존 제어 종료 확인 정책을 유지한다. 화면을 닫았다는 이유로 참여자 학습 완료·파일 보관 확인을 대신 체크하지 않는다.

## 확인 기준

1920×1080과 4K에서 시연/모아보기 전환이 한 번의 클릭으로 끝나고 현재 단계와 참여자 식별 정보가 보일 것. 새 손들기·중복 폴링·다중 요청·모임 전환·연결 대기에서 자동 지원 전환이 일관될 것. 시연→지원→복귀 시 초안과 송출을 유지하며 다른 참여자 화면을 전체 송출하지 않을 것. 제어 입력은 동의와 실제 영상·권한의 유효성을 계속 확인할 것. 모바일은 동일 기능에 접근할 수 있도록 세로 배치하고 PC의 고정 배치를 강제하지 않는다.
