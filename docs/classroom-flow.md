# 수업 화면 사용 가이드

승인된 [HTML 목업](prototypes/classroom/index.html)의 수업 흐름을 기존 실습실 기능에 연결한다. 새 모임을 만들거나 기존 모임을 고른 뒤 이용한다.

## 모임지기

1920×1080 기준 진행 화면은 중앙 작업·오른쪽 참여자·하단 안내를 고정해 사용한다. **도와주기 → 중앙 지원 → 내 시연·진행으로 돌아가기**로 이동하며, 자료·코드와 모임 도구는 같은 화면에서 패널로 연다. [진행 화면 사용법과 검증 범위](classroom-command-center.md).

1. **수업 준비**에서 제목·단계별 안내·예시 문장·텍스트 자료를 저장한다. **메모 연습 템플릿**은 오늘의 5줄 보고서 실습을 채운다. 이미 수정한 입력이 있다면 저장 전에 확인한다.
2. **수업 진행**에서 현재 안내 단계를 고르고 `시연 보기 / 함께 실행 / 개별 실습`을 전환한다. 방식과 안내만 바꾸며 참여자의 단계·파일·실행 중인 프로세스를 바꾸지 않는다.
3. 시연실은 **시연실 만들기**를 눌렀을 때만 별도 1인 샌드박스로 만든다. 모임과 같은 사양·AI 한도를 사용하므로 추가 자원이 든다. 기존 참여자 자리는 사용하지 않는다. 현재 모임 종료 시각을 넘지 않고 모임 종료 때 함께 정리한다.
4. 시연실 파일 편집기는 서버의 실제 파일을 읽고 저장한다. `수업 메모 넣기`는 이미 있는 메모를 유지한다. 저장 후 실습실 터미널이나 별도 탭에서도 같은 파일을 볼 수 있다.
5. **함께 실행**은 기존 수업 터미널 기능으로 대상을 선택하고 확인한 뒤 각각 실행한다. 전달 일시정지는 새 전달만 막는다. 현재 실행을 멈추는 일과 구분한다.
6. 참여자 지원을 열면 먼저 보기 상태다. 클릭·키보드 제어는 기존 별도 요청·허용 흐름을 거친다. 단계를 함께 보고 도와주되 완료·보관 확인을 대신 표시하지 않는다.
7. **제출·피드백**에서 참여자와 제출 버전을 골라 실제 저장된 내용을 읽고 의견을 남긴다.
8. **복습하기**는 저장한 녹화 링크와 단계별 위치를 이용한다. 녹화를 자동 생성·업로드하지 않는다. 외부 재생기의 시각 링크 지원 여부는 해당 서비스에 따른다.

진행 중 참여자가 늘면 **좌석 추가 → 1자리 추가 → 새 좌석 초대**를 사용한다. 기존 모임 조건과 종료 시각을 따르며, 모임당 최대 20자리다. 새 모임 생성은 상단 **설정 → 새 모임**에서, 기기 설정은 **설정**에서 연다. [좌석 추가와 복구 안내](classroom-seat-add.md).

## 참여자

1. 실습실의 **수업 안내**를 연다. 노트북에서는 편집기 옆 안내를, 휴대폰에서는 접었다 여는 안내를 이용한다. 모임지기 안내 단계와 나의 단계는 별개다.
2. **자료 → 수업 자료를 내 실습실에 넣기**를 누르면 모임에 저장된 텍스트 자료를 `work` 폴더에 만든다. 기존 파일은 덮어쓰지 않는다. 파일을 직접 내려받아 볼 수도 있다.
3. 자기 파일은 VS Code 탐색기에서 업로드하거나 파일을 끌어 놓는다. 수업 패널의 업로드 안내와 탐색기 열기를 참고한다. 안내를 열었다고 파일 업로드가 완료되는 것은 아니다.
4. 단계의 예시 문장을 복사해 OpenCode에 입력하고, 결과를 직접 읽고 고친다. 막히면 현재 단계로 도움을 요청한다.
5. 편집기에서 `결과.txt`를 **먼저 저장**한 뒤 **제출**한다. 서버가 내 샌드박스의 `/home/daytona/work/결과.txt`를 읽는다. 아직 저장하지 않은 편집기 내용은 제출되지 않는다.
6. **내 작업 받기**로 ZIP을 내려받는다. 내 컴퓨터에서 ZIP과 결과물을 직접 열어 본 뒤 **파일 보존 확인**을 표시한다. 단계 완료·제출·전송 기록·직접 보관 확인은 각각 다른 상태다.

## 저장과 접근 범위

- 수업 구성·진행·제출 버전·피드백은 서버에 저장하므로 새로고침으로 없어지지 않는다. 참여자 응답에는 자기 진행·제출만 포함한다.
- 결과.txt는 UTF-8 텍스트 64KiB 이하, 자리마다 최대 10회 제출이다. 같은 제출 ID는 중복 제출을 만들지 않는다. 시간 초과 후에는 같은 요청을 확인하며 새 ID로 자동 재실행하지 않는다.
- 수정은 관리 토큰으로만 한다. 8시간 보기 쿠키로는 수업 상태를 읽을 수 있고, 구성·피드백·시연 실행을 바꿀 수 없다. 기존 본인 전용 요청함·승인 보안 키 정책은 유지한다.
- 보안 키로 로그인한 같은 브라우저에서는 새로고침·새 탭에도 관리 인증을 복원한다. 최초 로그인부터 최대 8시간이며 새로고침으로 연장되지 않는다. 설정의 로그아웃은 복원 권한도 폐기한다. 업데이트 후 최초 한 번은 보안 키로 로그인해야 유지용 쿠키가 생긴다.
- 관리 복원은 HttpOnly·Secure·SameSite=Strict·호스트 전용 쿠키와 동일 출처 POST로만 한다. 기존 읽기 전용 보기 쿠키로 관리 권한을 얻을 수 없다. 개설 승인 때 별도 보안 키 확인은 유지한다.
- 시연실 입장 링크는 짧은 수명의 1회용 권한이다. 관리자 토큰을 다른 출처에 넘기지 않는다. localStorage·sessionStorage에 관리 토큰이나 시연 파일을 보관하지 않는다.
- 모임 종료 후 참여자 실습실 접근은 끝난다. 수업 구성과 제출 기록은 모임지기의 검토용으로 7일 보관하며 이후 알람으로 정리한다. 장기 보관할 결과물은 종료 전에 PC로 내려받는다.
- 종료한 모임은 **제출·피드백 / 복습하기 → 지난 모임 목록 불러오기**에서 고른다. 현재 실습실 선택은 바꾸지 않으며, 종료한 기록에는 피드백 저장·단계 변경·제어를 제공하지 않는다.
- 저장된 녹화 링크가 없으면 녹화가 없다고 표시한다. 단계 복귀는 파일이나 AI 실행 상태의 복원을 뜻하지 않는다.

## 구현·운영

실제 기능은 기존 Worker·Durable Object·Daytona 연결을 사용한다. 포크한 Moodle·Canvas·Open edX·BigBlueButton을 함께 설치한 구성이 아니다. 조사한 UX를 기존 실습실에 적용한 것으로, [조사와 OSS 선택 근거](research/teaching-platforms/2026-10-16.md)를 함께 보관한다.

검증은 공급자 자격 증명을 쓰지 않는 로컬 예시와 실제 State 코드로 수행한다. 실제 수업 중인 모임에 테스트 명령을 일괄 전달하지 않는다. 운영 배포 시에는 기존 비밀값·등록 키·진행 중 실습실을 교체하지 않는다.

2026-10-16 통합 검증에서는 자료 생성·기존 파일 유지·저장된 결과 제출·모임지기 피드백·새로고침 후 재조회·독립 시연실 파일 쓰기/읽기를 실제 Worker/State와 합성 공급자로 연결했다. PC 1366×768와 휴대폰 390×844에서 가로 넘침과 스크립트 오류가 없었다. Aside에서도 실제 통합 화면을 열어 확인했다. 이는 실제 Daytona IDE·AI 실행·SFU 영상망을 새로 검증했다는 뜻은 아니다.
