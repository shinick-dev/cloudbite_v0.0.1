Owner deployment procedure (from the intended worktree):
  npm run check
  node node_modules/wrangler/bin/wrangler.js types .artifacts/production/worker-configuration.d.ts --config wrangler.cloudbite.jsonc --env=
  node node_modules/wrangler/bin/wrangler.js deploy --config wrangler.cloudbite.jsonc --env= --dry-run
  node node_modules/wrangler/bin/wrangler.js deploy --config wrangler.cloudbite.jsonc --env= --secrets-file .artifacts/production/secrets.json --strict

Verify the account/Worker before deploying. Use the installed Wrangler version.

with independent MASTER_KEY and SETUP_TOKEN plus the Cloudbite Daytona/Nosana
keys. Never publish this directory, its operator HTML/QR, or the secrets file.
Owner security-key sign-in is at /cloudbite/requests (KO/EN). Its scoped HttpOnly
cookie survives reloads, new tabs and browser restarts until explicit logout,
key removal, or browser cookie deletion; the server has no eight-hour expiry.
Legacy admin, vault and studyroom policies are unchanged. See owner-session.txt.
First physical-key registration requires the private SETUP_TOKEN. Never register
test virtual authenticators in production; browser WebAuthn QA stays local.
Keep the original MASTER_KEY during redeployment so encrypted state remains
readable. No key reset or fake WebAuthn proof is needed for temporary access.
