## 무엇이 바뀌었나

기존 역할 고르기(처음 6개 + 접힌 All experts 검색)는 그대로 둔다. 새 탐색 메뉴는 없다.
bootstrap 에 선택 필드 `pool` 이 있을 때만 두 가지가 더 보인다.

1. **역할 카탈로그** — 처음에는 접힌 상자다. 펼치면 검색(이름·번호 `#61`·키워드·분야), 분야 선택, 보기(전체·실행 가능·계획 중)로 좁혀 24줄씩 보고 "N개 더 보기"로 늘린다. 첫 화면에 100개 체크박스를 늘어놓지 않는다.
   - 줄마다 계획 번호·이름·분야, 실행 역할 이름이 다르면 "runs as …", 상태 표시(실행 가능 / 계획 중 — 아직 실행 불가), 지식 상태(정리된 지식 자료 / 메타데이터 기반 / 지식 자료 없음), 평가 상태(늘 "평가 전")를 보인다.
   - 계획 중 역할의 상자는 늘 잠겨 있고 변경 이벤트를 받지 않는다. 선택(`S.selected`)에는 실제 실행 역할 id 만 들어가므로 계획 역할은 제출될 수 없다.
   - 이미 고른 역할은 검색·필터와 관계없이 목록 맨 위에 남는다.
2. **팀 제안** — "브리프로 팀 제안 받기" 버튼. 목표·이름·맥락에서 카탈로그 키워드를 찾아, 지금 카탈로그에 있는 실행 가능 역할만 최대 `limits().max`(≤5, 방문자는 세션 한도) 명을 고른다.
   - 정렬: 서로 다른 일치 키워드 수 → 우선 역할 → 번호. 무작위·점수·확신도 없음. 근거로 찾은 키워드를 보인다.
   - 영문 키워드는 낱말 단위(4자 이상은 앞부분 일치: threat → threats), 한글 등은 조사가 붙으므로 부분 일치.
   - 맞는 키워드가 없거나 브리프가 비었으면 그 사실을 밝히고 제안하지 않는다.
   - 제안은 보여 주기만 한다. **적용**을 눌러야 선택만 제안 역할로 바뀐다 — 실행·요청·타이머·방문자 한도 변화 없음. 제안 뒤에 사용자가 직접 바꾼 선택은 적용 전까지 그대로다.
   - 제안 뒤 브리프나 카탈로그가 바뀌면 "오래된 제안"이라고 알린다. 고치지 않은 예시 브리프가 언어 전환으로 번역된 것은 수정으로 보지 않는다.

## pool 정리 (화면 쪽 방어)

`normalizePool(raw, experts)` 는 서버 값도 의심한다.

- `entries` 배열이 아니거나 쓸 항목이 없으면 pool 없음 → 예전 화면. 깨진 pool 이 bootstrap 전체를 실패시키지 않는다.
- 항목 최대 100개, id 는 `pool-NNN`, 번호는 1–100 정수, 이름 필수. 중복 id·번호는 처음 것만.
- `available` 은 서버가 글자 그대로 `available` 이라 하고 `expertId` 가 실제 bootstrap 역할이며 다른 항목이 먼저 가져가지 않았을 때뿐이다. 아니면 계획 중이고 `expertId` 를 지운다.
- 화면은 권한을 만들지 않는다: `evaluation` 은 늘 `unvalidated`, 지식 깊이는 실행 역할 정의(`source.basis`)보다 높게 적지 않는다.
- 문자열 길이 상한(이름 120, 분야 라벨 60, 임무 400, 키워드 24개×40자, mappingNote 200). 모든 글자는 textContent 로만 그린다.

`PoolEntry`/`Pool` 타입은 런타임 계약(`ExpertPoolEntry`/`ExpertPool`)과 같은 모양으로 콘솔에 따로 둔다 — 빌드가 묶지 않는 변환이라 런타임 import 가 없고, 통합 전에도 `tsc -p tsconfig.client.json` 이 통과해야 하기 때문이다. 통합 시 `CloudbiteBootstrap.pool?: ExpertPool` 이 생겨도 `ConsoleBootstrap = CloudbiteBootstrap & { pool?: Pool }` 교차 타입은 같은 모양이면 그대로 맞는다.

## KO / EN

새 문구는 모두 `EN`·`KO` 사전에 있다. 언어를 바꿔도 검색어·분야·보기 선택·펼침 상태·제안(항목 id·찾은 키워드로 저장)·선택이 남고 새 언어로 다시 그려진다. 서버가 보낸 이름·임무·키워드는 번역하지 않는다.
