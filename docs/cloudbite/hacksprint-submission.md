# Cloudbite — Daytona HackSprint 제출 초안

## 한 문장

프로젝트 하나를 던지면 전문가 AI마다 전용 컴퓨터를 받아 직접 조사·계산·작성하고, 의사결정자가 그 과정과 산출물을 확인하는 전문가 작업 공간.

## 사용자와 문제

새 제품을 준비하는 창업자·프로젝트 리더는 기술·고객·가격·보안 등 여러 관점을 함께 검토해야 합니다. Cloudbite는 각 관점을 명확한 작업 지시와 결과물로 연결하고, 어떤 자료와 가정에서 의견이 나왔는지 확인할 수 있도록 합니다.

## 핵심 경험

공통 프로젝트와 자료 → 역할별 페르소나·작업 지시 → 전문가별 Daytona 샌드박스 → 파일·코드 도구와 Nosana 추론 → 산출물·의견 분포·소수 의견 → 다음 결정.

첫 시연은 ‘100인 AI 자문실 출시’ 프로젝트를 제품·기술·가격·UX·보안 관점에서 검토하는 흐름으로 준비합니다. 첫 구현은 프로젝트당 최대 5명, 동시 작업 최대 3명이며, 더 큰 전문가 풀은 이후 확장 대상입니다.

## 후원사 활용

- Daytona: 전문가마다 격리된 작업 환경을 만들고, 페르소나·프로젝트·작업 지시·결과 스키마 파일을 넣습니다. 환경 안에서 도구와 파일 작업을 실행하고 수명·취소·정리를 관리합니다.
- Nosana: 설정한 GPU 추론 엔드포인트에서 전문가 작업에 필요한 모델 추론을 제공합니다. 관리용 자격증명은 서버에 두고, 각 작업에는 좁은 범위의 호출 권한을 부여합니다.

## 재사용과 새 구현

기반은 자체 공부방 서비스의 샌드박스·자격증명 중계 구조입니다. 새 작업은 전문가 역할 패키지, 프로젝트 단위 실행, 결과 파일과 활동의 관찰, 종합 판단 화면입니다. pro-bably의 레지스트리와 작업 지시 구조를 참고하며 출처를 기록합니다.

## 데모에서 증명할 것

1. 같은 프로젝트가 역할별로 다른 작업 지시와 파일로 구성됩니다.
2. 전문가가 각자의 환경에서 도구를 사용해 결과물을 만듭니다.
3. 일부 작업 실패·취소가 다른 작업 결과와 구분돼 표시됩니다.
4. 종합 화면에서 원본 전문가의 근거와 산출물까지 확인할 수 있습니다.

## 구현 상태 표기

이 문서는 제출 초안입니다. 실제 Daytona 생성·Nosana 호출·브라우저 동작에 대한 검증 결과를 완료 후 추가합니다. 로컬 모의 실행과 실제 외부 실행을 구분하고, 미검증 상태를 완료된 기능처럼 발표하지 않습니다.
