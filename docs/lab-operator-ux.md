# 모임지기 화면 정리

2026-10-16 UX 검토와 전체 개선 승인에 따른 구현 계약. 아래는 통합 구현과 로컬 검수 결과다. 운영 배포 정보는 HANDOFF.md에 기록한다.

## 목적

모임지기 한 명이 설명·화면 송출·진행 확인·개별 지원을 함께 하는 상황에서, 지금 필요한 사람과 도구를 쉽게 찾는다. 기존 색상과 시각 체계를 유지하며 기능별 배치·노출 시점·명칭을 바꾼다. 새 UI는 관리 권한을 추가하지 않는다.

## 기능별 위치

| 위치 | 주요 작업 | 상세에서 찾는 도구 |
|---|---|---|
| 모임 진행 | 현재 모임 선택, 화면 모아보기, 도움 대기열, 내 화면 공유 | 선택한 참여자의 접속·서버 준비·명령 전달·파일·사용액 |
| 참여자 지원 | 한 사람 확대해서 보기, 별도 제어 요청 | 동의 후 클릭·키보드·한글 입력, 제어 끝내기, 영상 연결 진단 |
| 모임 진행의 배포·실행 | 코드·자료 전달, 명령 전달 일시정지 | 선택한 자리 터미널 함께 실행, 실행 중 프로그램 중단 요청 |
| 모임 도구 | 초대·연결·파일 보관 지원 | 시험 자리, 체크포인트, 같은 요청으로 복구, 실습실 교체, 조교 권한 |
| 설정 → 새 모임 | 새 모임, 자료, 기본 사양과 한도 | 직접 사양, 클립보드, 공유할 API 기능, 고급 설정 |
| 자동 미리보기의 회색 요청 자리 | 조건을 보고 바로 보안 키로 승인 | 조건 변경, 같은 요청 결과 확인, 요청 기록·알림 |
| 상단 설정 버튼 | 작은 창의 인증 상태, 기기 알림, 앱 설치 | 알림 기기·시험 알림·실제 수신 확인, 관리자 설정 진입 |
| 마무리 | 파일 직접 보관 확인 후 모임 종료 | 미확인 자리 경고와 기존 삭제 확인 |

## 보존하는 동작

- 실습실 편집기·터미널만 자동 미리보기한다. 참여자 PC 전체 화면을 요구하지 않는다.
- 클릭·키보드는 별도 참여자 허용 후에만 보낸다. `도와주기`로 화면을 여는 것만으로 제어를 요청하거나 허용하지 않는다.
- 제어 중인 대상·허용 상태·종료 방법을 계속 표시한다. 대상 전환·오류·만료 후 옛 대상에 새 입력을 보내지 않는다.
- 모아보기/선택 화면의 화질 전환과 실제 수신량 집계는 유지한다. 측정은 해당 탭의 영상 RTP 데이터이며 Cloudflare 청구량과 다르다.
- 권한은 관리·읽기 전용 모니터·화면 지원 세션의 기존 정책을 따른다. 관리자 8시간을 줄이거나 자동 연장하지 않는다.
- 같은 브라우저의 새로고침·새 탭은 보호된 쿠키로 원래 관리 인증을 복원한다. 최초 로그인부터 8시간이며 로그아웃하면 복원 권한도 폐기한다. 업데이트 후 한 번은 보안 키로 로그인한다.
- 개설 요청 목록의 본인 전용 Cloudflare Access 경계와 승인 때의 별도 보안 키 확인을 유지한다.
- 명령 전달 일시정지는 새 전달을 막는다. 이미 실행 중인 프로그램을 중단했다는 의미로 표시하지 않는다.
- 코드 전달과 실제 터미널 실행을 구분한다. 대상과 실행 효과를 확인한 뒤 해당 동작을 요청한다.
- 생성·교체·제어·전달 응답을 모르면 같은 요청의 상태를 확인한다. 화면 변경으로 새 요청 ID를 만들지 않는다.
- ZIP 전송과 참여자가 PC에서 열어 확인한 기록은 다르다. 모임지기나 조교가 대신 보관 완료로 표시하지 않는다.
- 화면의 연결·활동 상태는 학습 이해도나 과제 완료의 증거가 아니다.
- 로컬 메뉴 전환이나 목록 갱신이 공유 스트림·초안·진행 중 요청을 불필요하게 종료하지 않게 한다.

## 기본 노출과 상세 노출

진행 화면에서는 현재 모임·입장 수·남은 시간·상태 최신성, 화면 공유, 도움 대기열이 우선이다. 큰 빈 영상과 사용 불가능한 입력칸은 줄인다. 한 사람을 선택하면 그 사람의 확대 화면·상태·도구가 함께 열린다. 원격 입력 도구는 실제 허용 후 표시한다.

상단은 설정 버튼 하나이며 새 모임도 그 안에서 연다. 진행 중에는 좌석 추가 버튼으로 현재 조건의 한 자리를 열고 초대한다. [좌석 추가와 복구 안내](classroom-seat-add.md). 기기 알림의 긴 설명과 앱 설치 안내는 접어 둔다. 복구 도구는 보존하고 문제가 있는 자리에서 찾기 쉽게 연결한다. 명령 전달 일시정지를 깊은 메뉴에 숨기지 않는다. 종료는 마무리 단계에서 확인과 함께 수행한다.

## 접근성과 표시

- `hidden`이 레이아웃 CSS보다 우선하도록 하여 기본 사양과 직접 사양 입력칸이 동시에 보이지 않게 한다.
- 입력칸에 연결된 라벨, 표에 열 제목, 버튼에 실제 작업을 나타내는 이름을 제공한다.
- 현재 도움 요청과 미확인 과거 알림을 구분한다.
- 비활성 이유, 불러오는 중, 오래된 상태, 실패, 결과 불확실, 빈 목록을 구분한다.
- 1366×768 노트북, 390px 휴대폰, 200% 확대, 키보드 탐색을 확인한다. 글자·초점·대상·종료 조작이 화면 밖으로 사라지지 않게 한다.

## 검수 장면

실제 참여자·샌드박스·토큰을 쓰지 않는 `test/fixtures/lab-operator-ui.mjs`는 도움 요청, 오프라인, 입장 전, 전달 결과 불명확, 여러 모임, 개인 복습·합류 요청을 제공한다. `node test/fixtures/lab-operator-ui.mjs`로 localhost:8876에서 띄우며, 합성 예시 표시가 있다. Ctrl+C로 종료한다.

## 검토 근거

Impeccable의 독립 디자인 검토와 기계·브라우저 근거 검토를 합쳤다. 기존 탭 관찰은 당시 사용자가 펼친 폼과 과거 알림을 포함한 상태이므로 최초 진입의 기본 화면 통계로 일반화하지 않는다. 정적 검사 0건은 동적 UI나 접근성 통과를 뜻하지 않는다.

Mobbin에서 직접 열어 본 [Sprig 홈](https://mobbin.com/screens/f84e47cb-1071-4b39-b6c7-8b0b62e01d6e)의 작업·설정 분리와 [NN/g의 점진적 공개](https://www.nngroup.com/articles/progressive-disclosure/)를 참고했다. 전체 유료 라이브러리나 Mobbin MCP 검색을 이용한 것은 아니다.


## 구현·검수 기록 (2026-10-16)

StackBite의 Grok CLI `grok-4.7-build-fast`, reasoning `high`로 셸·참여자 지원·요청함을 별도 worktree에서 병렬 구현했다. 작업자 후보는 각각 `bc2c5ea`, `43f76b6`, `8cbf4f9`이며, 최종 소스와 부모의 통합 수정을 함께 반영했다. 독립 검수는 `cdd2f16`에서 관리 만료 후 메타데이터 재등장과 모니터 종료 시 독립 라이브 지원 중단을 발견했다. 두 경로를 수정한 후보는 `5e7e79c`이며 독립 재검수는 `5e7e79c`에서 두 결함과 지원 이동 경로의 수정을 확인해 PASS했다. 이후 부모가 상태 정보 미확인을 빈 모임으로 오인하지 않도록 문구·분기 1건을 보완하고 통합 검사를 40항목으로 확장했다.

- 타입·생성 소스 검사와 Wrangler 기본 환경 dry-run 통과. 새 리소스·마이그레이션·권한 정책 변경 없음.
- 통합 UX 40항목 통과: 네 메뉴, 선택 모임, 초안·포커스·공유 유지, 전달 중지 위치, 명시적 제어 동의, 대상 식별, 종료 취소, 관리·모니터 독립 만료, 승인 사양 고정과 같은 ID 결과 확인.
- 요청함 70항목 통과: 휴대폰·데스크톱, 요청 조건 펼치기, 승인 실패·결과 불명확·세션 만료, 새로고침 중 초안 유지, 알림 비활성 이유 유지.
- 기존 관리/모니터 회귀검사 98항목 통과(메뉴·접힘 변경에 맞춰 탐색 경로 조정). 지원 상태·방 분리·제어 종료, 화질/전송량 표시, 셸 탐색 검사도 통과.
- 개설·복구 57항목, 기존 개설 화면 36항목, 준비 상태 표 검사 통과. 실제 Monaco/xterm 입력 검사는 합성 SFU를 사용하며 실제 참여자 네트워크 품질을 뜻하지 않는다.
- Impeccable 최종 정적 탐지: 네 생산 소스에서 0건. 동적 UX·접근성의 전체 합격을 뜻하지 않는다.

Aside에서 로컬 합성 장면을 열어 검토했다. Aside의 뷰포트 조절이 지원되지 않아 여러 폭과 배율 검사는 격리된 Edge로 확인했다. 같은 1366×768 장면에서 영상 시작 위치는 세로 798px에서 592px로 올라왔다. 390px 휴대폰, 1366×768 노트북, 200% 확대 상당의 CSS 뷰포트에서 페이지 가로 넘침이 없었다. 모바일 지원 선택 후 해당 참여자 화면과 제어 요청에 접근할 수 있었다. 이 수치는 합성 장면의 배치 비교이며 실제 수업 이해도·연결 지연 개선의 측정값이 아니다.

실제 참여자·샌드박스·공급자 키를 사용한 회귀 실험과 수업 중 사용성 평가는 이번 로컬 UI 검증에 포함하지 않는다. 다음 모임에서 도움 요청을 찾는 시간과 도구를 찾느라 설명이 끊긴 횟수를 관찰해 조정한다.


추가 기존 회귀검사도 병렬 작업자가 전환했다(`1f4077b`, 통합 `b826a64`). 현재 모임 선택과 실제 메뉴·summary 클릭으로 초대·QR·클립보드·코드 초안·생성 복구·공유 중지 경로를 유지하며 모바일 139항목, 카드 106항목이 통과했다. 부모는 화면 API 흉내를 `/api/lab/live/session`과 `/api/lab/live/status` 두 경로로만 한정해 예상하지 못한 요청이 숨겨지지 않게 하고, 통합 main에서 두 검사를 다시 실행했다. 건너뛴 항목은 없다.
