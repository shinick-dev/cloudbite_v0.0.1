# 새로고침 후 관리 인증 유지

보안 키 로그인 후 같은 브라우저의 새로고침·새 탭에서도 원래 관리 세션을 복원한다. 8시간의 원래 만료 시각은 그대로이며, 복원할 때 새 토큰이나 보기 세션을 만들지 않는다. 업데이트 전의 읽기 전용 쿠키는 승격하지 않으므로 배포 후 한 번은 보안 키로 로그인해야 한다.

## 구현

- 로그인 응답을 페이지가 받은 뒤, 방금 발급된 웹 관리 토큰으로 `POST /api/lab/admin/session/remember`를 호출한다. CLI 토큰과 3분 넘은 로그인은 저장하지 않는다.
- `__Host-lab_admin`은 Path=/, HttpOnly, Secure, SameSite=Strict이며 원래 세션의 남은 시간만 보관한다. localStorage·sessionStorage·URL에는 저장하지 않는다.
- `POST /api/lab/admin/session`은 정확한 Origin과 Fetch Metadata를 확인하고 기존 웹 토큰의 유효성을 State에서 확인한다. 쿠키만으로 다른 관리 API를 호출할 수 없다. 중복 쿠키·외부 출처·큰 본문은 거부한다.
- 로그아웃은 보기 쿠키와 관리 복원 쿠키를 지우고 서버의 해당 토큰도 폐기한다. 메모리에 토큰이 없는 복원 도중에도 쿠키로 폐기할 수 있다. 헤더와 쿠키의 토큰이 다르면 둘 다 폐기한다.
- 로그인 응답에서 바로 쿠키를 설정하지 않는다. 페이지가 이미 알고 있는 토큰만 유지 쿠키로 저장하므로, 저장 응답이 로그아웃보다 늦게 도착해도 폐기된 권한이 살아나지 않는다. 화면의 세대 검사도 늦은 응답을 무시한다.
- 기존 개설 승인 보안 키 확인·본인 전용 요청함·참여자 제어 동의·독립 보기 세션 정책을 바꾸지 않는다. 새 바인딩·비밀값·마이그레이션은 없다.

## 검증

`test/lab-admin-refresh.mjs`는 실제 Worker·State와 격리 Edge 브라우저를 연결한다. WebAuthn 발급 입력은 합성이며 실제 키·Daytona·외부 AI는 사용하지 않는다. Aside가 제공하지 않는 가상 보안 키와 응답 지연 주입만 이 격리 테스트에서 사용한다.

9개 시나리오에서 반복 새로고침·새 탭·다른 브라우저 격리, 원래 만료 시각 유지, 저장소·쿠키 속성, Origin·본문 경계, 쿠키만으로 관리 불가, CLI 거부, 만료, 복원 중 로그아웃, 로그아웃 후 늦은 Set-Cookie 무효화를 검사한다. 기존 모니터·로그아웃 경합·모임지기 UI 검사도 함께 실행한다. 실행 결과와 운영 반영 증거는 `.artifacts/classroom-admin-refresh-20261016`에 기록한다.
