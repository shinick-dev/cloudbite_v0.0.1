# 실습실 자동 미리보기와 탭 지원

참여자가 입장하면 현재 실습실의 편집기·터미널 화면이 모임지기에게 자동으로 보입니다. 참여자의 ‘내 화면 공유’ 버튼이나 브라우저에서 창을 고르는 단계는 없습니다. 개인 PC 전체와 다른 탭을 캡처하는 기능은 아닙니다.

입장 화면에 자동 공유 안내가 있고, 실습실 막대에 **실습실 화면 자동 공유 중**이라고 표시합니다. 화면 보기는 기본으로 연결되며, 클릭·키보드 조작은 참여자가 허용한 뒤 시작합니다.

## 모임 시작

1. 모임지기는 `/lab`을 새로고침하고 보안 키로 로그인합니다. 관리 권한은 최대 8시간입니다.
2. 참여자는 자기 초대 링크의 자동 공유 안내를 읽고 기존 **입장** 버튼으로 들어갑니다.
3. 모임지기의 **모임 화면**에 해당 자리의 영상이 나타납니다. 동시에 받는 영상은 최대 8개입니다.

이전 버전으로 열려 있던 실습실은 새로고침해야 자동 연결 코드를 받습니다. PC Chrome·Edge를 기준으로 확인합니다. 모임지기의 **들어가 보기**로 연 탭은 참여자 송출에 끼어들지 않습니다.

## 모임지기 화면

- **크게 보기 / 작게 보기**: 자리 영상을 확대하거나 화면 벽으로 돌아갑니다.
- **영상 보기 멈추기 / 영상 보기**: 모임지기 기기의 영상 수신을 끊거나 다시 받습니다. 참여자는 계속 작업할 수 있습니다.
- **영상 다시 연결**: 해당 자리의 수신 연결을 다시 시도합니다.
- 다른 자리를 보려면 안 보는 자리의 **영상 보기 멈추기**로 8개 연결 상한 안에서 선택합니다.

실습실 문서의 입력·스크롤·내용 변화를 감지해 갱신하는 자동 미리보기입니다. 기본 모아보기는 작업 중 약 1초, 유휴 약 2초 간격을 목표로 합니다. **크게 보기**로 선택한 자리는 작업 중 약 0.5초, 유휴 약 1.5초 간격을 목표로 합니다. 캡처 시간에 따라 간격을 늘려 느린 PC에 작업이 쌓이지 않게 하며, 동시에 여러 캡처를 실행하지 않습니다. 보이지 않는 요소를 제외하고 화면 배치·글자·색상에 필요한 스타일만 복사합니다. 디코딩이 끝난 이미지를 추가 화면 그리기 이벤트까지 기다리지 않고 사용해, 가려진 탭에서 이미지마다 대기가 누적되는 것을 줄입니다. 백그라운드 탭은 5초 간격을 기본으로 하되 브라우저의 절전·탭 정지 정책에 따라 더 늦어질 수 있습니다. 최신 영상이 없으면 새 원격 입력을 막습니다. 이 간격은 캡처 목표이며, 영상 중계·네트워크를 포함한 수신 지연을 보장하는 값은 아닙니다.

기본 모아보기는 최대 **640×400·0.4Mbps**입니다. 크게 보기로 선택한 자리는 최대 **1920×1200·4Mbps** 안에서 화면 비율을 유지하고, 고밀도 디스플레이에서는 기기의 픽셀 밀도를 최대 2배까지 반영합니다. 선택한 화면의 글자·해상도 보존을 브라우저에 우선 요청합니다. 각각의 Mbps 값은 전송 상한이며 일정하게 사용하는 양이나 전체 통신량의 절대 상한을 뜻하지 않습니다. 실제 사용량과 화질은 회선·브라우저가 조절합니다. 지원 브라우저에서는 수신 영상의 `jitterBufferTarget`을 0으로 요청해 불필요한 재생 대기를 줄입니다. 이 값은 브라우저에 대한 선호 설정이며 실제 버퍼를 강제로 없애는 보장은 아닙니다([API 설명](https://developer.mozilla.org/en-US/docs/Web/API/RTCRtpReceiver/jitterBufferTarget)). 작은 카드에서 글자를 읽기 어려우면 **크게 보기**를 사용합니다.

실제 브라우저 화면과 글꼴·일부 효과가 조금 다를 수 있습니다. 다른 출처의 미리보기 iframe은 제외하며, 캔버스 읽기 등이 실패하면 오류로 알립니다. 화면 크기가 바뀌면 새 크기의 화면이 만들어질 때까지 제어를 막고, 15초 넘게 새 캡처가 없을 때도 새 입력을 막습니다.

주소가 비어 있는 편집기 내부 이미지 요소는 캡처에서 제외합니다. 모임지기에게 받은 화면 공유 창도 다시 송출하지 않습니다. 두 화면을 서로 반복해서 담거나, 공유가 끝난 빈 영상 요소 때문에 캡처가 실패하는 것을 막습니다.

모임지기가 참여자에게 보내는 **🖥 화면 공유 시작**은 별개의 기능입니다. 이 방향은 모임지기가 브라우저에서 공유할 화면을 직접 고릅니다. 두 방향 모두 소리는 보내지 않습니다.

## 조작을 도와주기

1. 모임지기가 자리의 **제어 요청**을 누릅니다.
2. 참여자가 배너의 **5분 동안 제어 허용**을 직접 누릅니다. **거절**도 선택할 수 있습니다.
3. 양쪽에 제어 중 안내가 보입니다. 영상 안을 클릭하거나 영상에 포커스를 주고 키보드를 입력합니다.
4. 모임지기의 **제어 끝내기**, 참여자의 **제어 즉시 끝내기**, 최대 5분 만료 중 먼저 오는 때에 종료됩니다.

거절·철회는 서버 응답 전에 참여자 탭의 입력부터 차단합니다. 제어가 끝나도 자동 미리보기는 계속됩니다. 이미 적용된 입력은 되돌리지 않습니다. 실습실 교체나 송출 세대가 바뀌면 예전 동의를 이어 쓰지 않습니다.

한글·긴 문장은 영상 아래 입력칸에 적고 **입력 보내기**를 누릅니다. 한 번에 1,000자까지입니다. 오른쪽 클릭·두 번 클릭·휠을 지원합니다. 영상이 일시정지돼도 **제어 끝내기**는 누를 수 있습니다.

운영체제의 다른 프로그램이나 기본 파일 선택 창은 제어할 수 없습니다. 비밀번호 칸에는 텍스트를 보내지 않으며, 실습실 막대와 제어 요청 배너도 원격 클릭 대상에서 제외합니다.

## 세션과 종료

| 대상 | 수명과 종료 |
|---|---|
| 관리 권한 | 로그인부터 최대 8시간. 페이지 메모리만 사용하므로 새로고침하면 다시 확인 |
| 모임 화면 | 별도 쿠키로 처음 발급부터 고정 8시간. 로그아웃하면 이 기기의 수신·제어 종료 |
| 참여자 자동 송출 | 실습실 문서가 열려 있는 동안. 탭 닫기·이동, 모임 종료·만료 때 정리 |
| 클릭·키보드 | 참여자 허용부터 최대 5분, 양쪽 종료·철회·모임 종료 중 먼저 오는 때까지 |

모임지기 로그아웃은 참여자 브라우저 문서를 닫지 않습니다. 참여자의 자동 송출은 실습실 탭을 떠나거나 모임이 끝날 때 종료됩니다. 탭이 상태를 보내지 않으면 서버는 약 2분 뒤 공유를 오래된 것으로 봅니다.

## 안 될 때

- **화면이 안 나타남**: 참여자가 실습실을 열었는지, 막대의 자동 공유 상태와 오류 안내를 확인합니다. 이전 버전 탭을 새로고침하고 모임지기는 **영상 다시 연결**을 누릅니다.
- **영상 갱신 지연**: 참여자와 모임지기 모두 해당 화면을 앞으로 가져와 최신 영상을 확인합니다.
- **자동 연결 실패**: 간격을 늘려 재시도합니다. 한 자리에서 10초 안에 네 번을 넘겨 시작하면 잠시 거절하므로 연속 새로고침 대신 10초 이상 기다립니다.
- **다른 실습실 탭의 화면 공유 중**: 같은 자리의 다른 탭이 송출 중입니다. 실제 작업할 탭을 앞으로 가져옵니다.
- **네트워크에서 영상이 안 옴**: 현재 STUN을 쓰고 TURN은 없습니다. UDP가 막힌 망에서는 연결이 안 될 수 있습니다. **들어가 보기**로 작업 내용을 확인하고 말로 안내합니다. 이 보기는 참여자의 실시간 화면과 별개입니다.
- **요청 결과 확인 필요**: 같은 **제어 요청**으로 결과를 확인합니다. 새 요청을 겹쳐 보내지 않습니다.
- **입력 결과 확인 필요**: 제어를 끝내고 참여자와 실제 적용 결과를 확인한 뒤 다시 요청합니다.
- **관리 만료**: 보안 키로 다시 확인합니다. 이전 버전 토큰은 다시 로그인해야 8시간을 받습니다.

## 모임 전 두 사람 확인

1. 두 PC에서 모임지기 `/lab`과 참여자 실습실을 각각 엽니다.
2. 참여자가 공유 버튼을 누르지 않아도 편집기·터미널이 보이는지 확인합니다.
3. 참여자가 편집기 글자와 터미널 출력을 바꾸고 모임지기 화면이 갱신되는지 봅니다.
4. **제어 요청 → 거절**을 확인한 뒤 다시 요청해 **5분 동안 제어 허용**을 누릅니다.
5. 클릭·한글·휠을 확인하고 참여자가 **제어 즉시 끝내기**를 누릅니다. 새 입력은 멈추고 영상은 계속 보여야 합니다.
6. 참여자가 탭을 닫으면 해당 송출이 끊기는지 확인합니다.

자동 검사는 DOM 화면 생성, 실제 편집기·GPU 터미널, 송출과 제어를 나누어 검증합니다. 실제 모임 전체의 부하·네트워크·참여자 경험은 다음 모임에서 별도로 기록합니다.

`tools/real-live-capture.mjs`는 실제 Daytona code-server 문서와 실제 SFU 수신 프레임을 확인하는 별도 통합 검사입니다. `tools/realdev.ps1 -Test tools/real-live-capture.mjs`로 실행하며, 운영 모임과 분리한 임시 자리 하나를 만들고 종료 시 정리합니다. 소량의 Daytona 비용이 발생합니다. 캡처 오류를 재현한 뒤 받은 영상까지 확인해야 하며, API 성공만으로 영상 성공을 판단하지 않습니다.

### 갱신 속도 회귀 검사

`test/lab-dom-capture-ui.mjs`는 실제 Monaco·xterm WebGL이 있는 격리 브라우저에서 색상 변경이 캡처 픽셀에 반영되는 시간을 5회 측정합니다. 1400×900 화면의 불필요한 축소 방지, 큰 화면의 픽셀 상한, 고밀도 화면, 비밀번호 마스킹, 오버레이 제외, 종료 후 캡처 중단도 확인합니다.

`GW_LIVE_REAL_RTC=1`, `GW_LIVE_DOM_REAL=1`로 `test/lab-live-ui.mjs`를 실행하면 같은 편집기 fixture의 변경 픽셀이 실제 SFU를 거쳐 모임지기에게 도착하는 시간과 Full HD 수신을 확인합니다. 실제 Daytona code-server 문서 호환성 검사는 위 별도 통합 도구의 범위이며, 이 fixture의 성능 측정을 실제 모든 참여자의 속도로 일반화하지 않습니다.

업데이트 후 모임지기 페이지와 참여자 실습실 탭을 각각 새로고침해야 이미 실행 중인 송출 코드도 교체됩니다. 새 실습실을 만들 필요는 없습니다. 실습실 파일은 유지되지만, 저장하지 않은 편집 내용은 먼저 저장합니다.

2026-10-16 측정: 같은 로컬 캡처 fixture에서 변경 반영 중앙값은 3437ms에서 512ms로 줄었습니다. 실제 SFU와 편집기 fixture의 1920×1080 수신은 5회 중앙값 520ms·최대 1054ms였습니다. 실제 수강생 PC·네트워크 및 이번 설정의 실제 Daytona 문서 성능을 측정한 값은 아닙니다.

## 모아보기 부하와 전송량

한 모임지기 탭에서 한 자리만 크게 볼 수 있습니다. 다른 자리를 크게 보면 이전 선택은 모아보기로 돌아갑니다. 제어 요청도 해당 자리를 크게 선택하지만, 클릭·키보드 권한은 여전히 참여자의 별도 허용이 있어야 합니다. 영상 연결을 다시 만들지 않고 캡처 크기·주기와 브라우저 인코더 설정을 전환합니다.

선택 요청은 15초 유효하며, 활성 화면이 갱신합니다. 탭 숨김·종료·영상 보기 중지 시 해제를 시도하고, 응답이 없어도 유효시간 만료 뒤 참여자의 다음 상태 확인에서 기본 모드로 돌아갑니다. 여러 모임지기 창에서 같은 자리를 보면 유효한 고화질 요청 하나라도 있는 동안 고화질을 유지합니다. 하나의 원본 영상을 공유하므로 다른 창의 선택도 영향을 줍니다. 이 유효시간은 8시간 관리·모임 화면 인증 시간과 별개입니다.

상단은 이 탭에서 받은 **참여자 영상 수신량·현재 Mbps**, 이 탭에서 보낸 **모임지기 영상 송신량·현재 Mbps**를 표시합니다. 자리별 누적 수신량과 참여자 탭의 송신량도 표시합니다. 통계는 약 5초 간격으로 읽고 메모리에서만 유지합니다. 새로고침·모임 화면 세션 종료 시 초기화하며 재연결 시 같은 탭의 누적량은 보존합니다.

이 값은 브라우저가 보고한 영상 RTP 데이터로, 통신 헤더·다른 모임지기 창·다른 서비스·다른 시청자에게 중계한 복사본은 포함하지 않습니다. **Cloudflare의 계정 전체 사용량·무료 잔여량·청구액이 아닙니다.** 통계 미지원·확인 실패는 측정 대기로 표시하며 실제 0으로 단정하지 않습니다.
